# HyruleM 0.5.0-preview.3 — instalação nativa e diagnóstico

Os relatórios da [issue #4](https://github.com/KnightCZS/HyruleM/issues/4) mostram um processo com `preview_abi: 1`, sem `hm_world_status`, e executável diferente do pacote da prévia 2. Portanto, aquele teste ainda usou o adaptador antigo; não confirma o comportamento da correção ABI 2.

Esta atualização corrige o caminho de instalação e abertura:

- **Iniciar-Nativo.cmd** confere e, quando necessário, instala o runtime e o gerador na instalação selecionada no launcher, com backup e restauração em falha. Não abre o launcher após falha de instalação.
- Abrir **HyruleLauncher.exe** diretamente dentro do pacote também ativa o modo nativo. Antes de preparar o jogo, o launcher confere a identidade do executável selecionado e exige a identificação ABI 2.
- Configurações UTF-8 com acentos são lidas corretamente pelo Windows PowerShell. O instalador informa qual executável atualizou.
- A mensagem de falha nativa permanece após a desconexão. O diagnóstico consulta os dois clientes e diferencia runtime antigo, biblioteca sem atualização, callback parado e estado do ator. `native_ready` continua reservado à Gen1 completa.

## Como atualizar

1. Feche os dois jogos **e o launcher antigo**. Extraia o ZIP inteiro em uma pasta nova.
2. Execute **Iniciar-Nativo.cmd**. Ele utiliza a instalação já selecionada no launcher; aguarde a confirmação de runtime ABI 2.
3. Se ainda usava ABI 1, abra a configuração do Savage Wind e reconstrua a biblioteca do jogo com o gerador atualizado. Volte ao launcher deste pacote, hospede o servidor novo e conecte os dois clientes no mundo aberto.
4. Se o Link remoto não aparecer, mantenha os dois jogos abertos e execute **Diagnosticar.cmd**. Envie os dois relatórios com `native-preview-diag.3`.

Protocolo 3 / ABI 2, mantendo as correções e a camada inicial de vida dos monstros da prévia 2. **Não é uma confirmação de visibilidade em gameplay.** PvP, coleta, IA por proximidade e mundo completo continuam pendentes. Nenhum arquivo do jogo está incluído. A issue permanece aberta para validação com o runtime correto.
